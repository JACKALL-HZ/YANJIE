# 历史完整报告设计

## 目标

让每次推演都能在历史页恢复为一份可阅读、可继续的完整报告，并保证会话归属与用户画像快照在推演结束后保持稳定。

## 方案选择

采用“会话快照 + 事件时间线”。`simulation_sessions` 保存当前可恢复状态和冻结的用户画像；`simulation_events` 保存每年四个 Agent 的行动与原因；时间线保存年末世界状态和指标变化。历史报告读取这些已落库数据，不依赖浏览器内存中的聊天消息。

不采用前端临时拼装，因为刷新后会丢失。也不引入完整事件溯源重放，因为 MVP 只需稳定阅读和恢复，不需要任意版本回放。

## 数据边界

- `SimulationSession` 是报告根记录，包含场景、阶段、当前年份、决策变量、冻结画像、世界状态、时间线、结局、评分、风险与行动计划。
- `SimulationEvent` 是 Agent 回合审计记录，保存 `year`、`agent`、`action`、`state_diff` 和中文可读原因。
- 用户原话、意图分类、三分支预览及最终选择需作为会话级决策记录保存；它们不能只存在前端或临时 `agent_states`。
- 匿名会话通过稳定的浏览器会话标识查询；登录用户按 `user_id` 查询。会话详情与报告必须复用同一归属校验。

## 接口

- `GET /api/sessions` 返回当前归属下的历史摘要，统一使用 `id` 字段。
- `GET /api/sessions/{id}` 返回完整结构化会话详情，包括画像快照、决策记录、逐年时间线和 Agent 审计记录。
- `GET /api/simulations/{id}/report` 返回 Markdown 下载内容；新增结构化报告接口供页面渲染，避免将 Markdown 解析为 JSON。
- 仅 `paused` 会话展示“继续推演”；`horizon_review` 会话展示续推/结算控制；`completed` 会话只允许复盘追问。

## 前端

历史列表显示场景标题、创建时间、状态、年数和评分。详情页按以下顺序展示：画像快照、初始条件、用户决策与分支选择、逐年指标摘要、四 Agent 原文、结局与评分、风险和行动计划。

页面读取结构化详情 API；Markdown 仅用于下载。字段名必须映射为中文指标名，不能显示内部 action ID 或原始变量名。

## 错误与兼容

- 无归属权限统一返回 404，避免泄露会话存在性。
- 没有画像、没有决策记录或尚未结算时，报告显示明确的空状态，不报错。
- 已有会话若没有新增决策记录，仍可从时间线与 Agent 事件生成基础报告。

## 验收

1. 新推演后，历史列表能看到同一归属下的会话。
2. 修改用户画像后，旧会话报告仍显示启动时的画像快照。
3. 报告能显示每年的四 Agent 原文、用户决策/分支和指标变化。
4. 刷新页面后，完整报告仍可读取。
5. 历史页使用结构化接口渲染；Markdown 下载不再被当作 JSON。
6. 完成模块相关测试和前端构建；全量回归中会话、日记、画像快照失败归零。
