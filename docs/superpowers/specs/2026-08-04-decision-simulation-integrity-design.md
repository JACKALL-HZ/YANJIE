# 决策推演可信度、分支与历史复盘设计

**状态：已确认，待实现**

## 目标

修复当前推演中“闲聊推进年度、Agent 同质化、激进决策只被劝阻、过程不能完整复盘”的问题。升级后的系统必须让用户能够看懂每一轮发生了什么、为什么发生、自己选择了什么，以及不同选择会带来什么后果。

本设计分为共享底座、推演可信度、完整历史报告三部分实施；它们共享同一套会话、事件和所有权契约。

## 已确认的产品决策

- 用户提出激进经营方案时，先生成预览分支，用户选择后才改变主时间线。
- 预览至少包含：坚持用户方案、采纳专家建议、低成本替代方案。
- 未登录用户也应跨刷新保留自己的历史；登录后归并为账户历史。
- 启动时仍由用户选择推演年限。年限是经营周期，不是对话轮数。
- 周期届满后进入周期检查点，询问是否续推或结束结算，绝不自动以“时间耗尽”结局。
- 所有 Agent 的用户可见内容必须为通俗中文，内部变量名、下划线和无解释英文术语不得露出。
- 所有 Agent 都必须结合本次推演冻结的用户画像；资料缺失时必须说明不确定性，不能编造事实。

## 现状与根因

- `resume` 把任意用户文本写入 `user_message` 并直接推进下一经营年，因此“好吧”也会消耗年度。
- 最新用户消息只传给个人与风险 Agent，市场和环境 Agent 无法围绕当前决策分析。
- `SimulationMessage` 已有表但没有形成完整的对话写入链路；报告接口返回 Markdown 下载内容，历史页却按 JSON 使用。
- 流式端点额外发出 `sequence=0` 的开始事件，引擎也从 `0` 开始，导致序号重复。
- 场景的数值阈值、文案和 Agent 输出之间没有统一的可读性层。

## 1. 会话、时间与意图状态机

### 1.1 启动快照

新增 `SimulationConfig` 作为会话启动快照，至少包括：`planned_years`、场景、初始决策变量、成功标准和本次推演用户画像。`planned_years` 的合法范围为 1 至 10 年，默认 3 年。

用户资料合并规则为：本次表单覆盖已保存画像；合并后的结果写入会话快照。之后编辑画像只影响未来会话，不影响已有会话或报告。

### 1.2 输入分类

用户文本先由 `IntentClassifier` 产出受限枚举，不允许文本直接驱动引擎：

| 类型 | 例子 | 行为 |
| --- | --- | --- |
| `question` | 怎么盈利 | 生成向导回答，不推进年度 |
| `casual` | 好吧、我想想、再看看 | 确认当前暂停状态，不推进年度 |
| `business_decision` | 请明星代言、加大营销预算 | 创建待评估决策和预览分支 |
| `branch_choice` | 选择坚持代言 | 提交已选分支，推进一个年度 |
| `horizon_control` | 再推演 3 年、现在结束 | 扩展周期或终局结算 |
| `clarify` | 说得更激进一点 | 请求必要补充信息，不推进年度 |

分类失败默认进入 `clarify`，不得猜测为正式经营决策。`casual`、`question` 和 `clarify` 永远不会改变世界状态或年度。

### 1.3 周期检查点

一项已提交的经营决策最多推进一个年度。完成第 `planned_years` 年后，会话进入 `horizon_review`，并展示本周期结算摘要。用户可以续推 1、3 或 5 年，或选择结束并结算。

续推是系统控制事件，不是经营动作，也不调用 Agent。续推后的 `planned_years` 仍不得超过硬上限 10。达到硬上限时显示“已达到本次服务的 10 年上限，请结束结算或开启新推演”，不得显示含混的“时间耗尽”。

## 2. 决策预览与确定性分支

### 2.1 决策目录

自然语言先映射为 Pydantic `ProposedDecision`，其字段包含决策类别、目标、预算、时长、必要约束和匹配的场景动作 ID。场景 JSON 提供唯一的业务事实：可执行动作、参数范围、确定性效果、风险区间和替代动作。

未映射到决策目录的请求只能作为待评估提案，系统要求用户补充预算或范围；LLM 不得编造现金流、客流或利润效果。明星代言及低成本联名等分支，必须先作为奶茶场景的明确目录项和效果规则加入场景数据。

### 2.2 分支流程

1. 用户提交 `business_decision`。
2. 系统记录原话和标准化提案，所有 Agent 评估同一提案。
3. 纯函数引擎从当前快照派生三条预览分支：用户方案、专家推荐、低成本替代。
4. 每条分支返回同一组可比较指标：现金流、日客流、月利润、风险等级和最坏损失。
5. 用户选择分支；只有选择的分支生成 `decision_committed`，并在下一次年度结算中改变主线世界状态。

预览分支是只读的短期模拟，不改变主线状态。未选择的分支保留在历史中，供报告说明“比较过什么、为何选择”。

## 3. 多 Agent 协作契约

所有 Agent 必须收到完整的 `DecisionContext`：当前世界状态、最新标准化提案、本年度策略、场景检索证据，以及角色相关的画像摘要。用户可见的结构化输出固定为：`我的判断`、`依据`、`主要代价或机会`、`建议动作`、`把握度`、`画像参考`。

| Agent | 固定立场和评价重点 | 画像重点 |
| --- | --- | --- |
| 市场 | 增长机会、获客增量、客群匹配、品牌传播 | 城市、行业经验、资源网络、目标 |
| 环境 | 本地竞争、季节、政策、客群和渠道环境 | 城市、可投入时间、外部约束 |
| 个人 | 创始人能力、精力、家庭负担、执行可行性 | 技能、工时、家庭、动机 |
| 风险 | 沉没成本、最坏损失、止损线、现金跑道 | 资产、负债、收支、风险偏好、损失上限 |

Judge 只能汇总冲突、证据不足和推荐，不得替用户否决决策或直接改变世界状态。它执行观点多样性校验：若 Agent 的建议和理由高度重复，退回要求按各自维度重写。若独立证据确实都指向同一结论，则明确展示“专家共识”及共同证据，而不是为了制造戏剧性编造异议。

把握度由纯函数根据证据完整度、资料缺失、决策不确定性和风险敞口计算并限制在合理范围。LLM 可以提供估计，但不得直接决定最终展示值。

## 4. 数值与中文可读性

新增纯函数 `MetricNarrator` 和术语表，所有年度摘要、Agent 指标引用、风险与报告都必须调用它。

- `customer_flow` 显示为“日客流”，`monthly_profit` 显示为“月利润”，`payback_ratio` 显示为“回本进度”。
- 阈值状态统一为“远低于、略低于、处于区间、略高于、显著高于”。例如 145 对 150 至 350 的行业区间，必须表述为“略低于行业稳态下限 5 杯”。
- 输出校验禁止内部字段名、未翻译英文、末尾下划线和没有释义的缩写。
- 每个年度结算先展示简短指标卡，再展示 Agent 内容。指标卡列出当前值、相对上一年的变化和主要因果动作。

## 5. 完整历史、匿名身份与报告

### 5.1 所有权

首次匿名访问时，后端签发 256 位随机匿名令牌，并设置 `HttpOnly`、`SameSite=Lax` 的 `visitor_token` Cookie；数据库仅保存该令牌的 SHA-256 摘要。匿名用户可跨刷新访问自己的会话，但不能枚举其他匿名用户会话。登录后，将同一匿名凭证拥有的会话归并到该账户；归并过程写入审计事件。

### 5.2 事件记录

保留会话当前快照用于快速读取，同时把以下记录追加为有全局递增序号的不可变会话事件：

- 会话创建与冻结配置
- 用户消息、向导提问与回答
- 决策提案、分支预览和分支选择
- 每个 Agent 的结构化判断和 Judge 汇总
- 每年开始、每年结算、指标变动摘要
- 周期检查点、续推或结束选择
- 终局结算、失败摘要和画像归并

SSE 事件必须先成功写入后再发送。恢复推演从数据库最后一个序号的下一位开始，保证全会话严格单调。流式校验或运行失败必须发送并记录一次 `simulation.failed`，不能静默断流。

### 5.3 报告与历史页

`GET /report` 返回类型化 JSON 报告，包含启动配置、画像快照、当前状态、逐年指标卡、对话、Agent 判断、分支比较、周期变更和终局结果。暂停会话同样返回已发生的完整过程，并明确“等待你的决定”。

Markdown 导出改为独立下载端点。历史页使用报告字段渲染可读组件，不再把 JSON 原样打印。任何报告读取都必须经过账户或匿名设备所有权校验。

## 6. 场景自定义指标与场景库扩充

### 6.1 指标模型

当前十个场景全部复用现金流、客流、竞对数、月利润和回本进度，导致考研、留学、买房、求职等场景的指标失真。引擎必须改为从场景 JSON 读取 `metric_definitions`，不再把创业世界状态字段作为所有领域的固定契约。

每个 `MetricDefinition` 至少定义唯一标识、中文名称、单位、显示精度、方向、健康区间、风险阈值和叙述规则。运行状态存为 `metrics: dict[str, float]`；结局、评分、风险、年度摘要、分支比较和报告一律通过指标定义读取数据。领域代码不得硬编码“客流”或“月利润”。

场景动作的效果、干预规则、结局条件与预览分支也只引用该场景已声明的指标。加载器拒绝动作引用未定义指标、阈值缺少中文名称、或缺少可读单位的场景文件。

### 6.2 现有场景升级

以下是现有场景的最小领域指标集；具体阈值和动作效果由各自 JSON 提供：

| 场景类别 | 指标 |
| --- | --- |
| 创业 | 现金储备、日客流或活跃用户、月利润、复购率或留存率、竞争压力 |
| 考研与考公 | 备考进度、模考成绩、上岸概率、心理负荷、剩余预算 |
| 留学与高考志愿 | 学术竞争力、申请或录取概率、语言或学业进度、预算缺口、适配度 |
| 买房与租房买房 | 首付储备、月供收入比、房价可负担度、通勤满意度、政策风险 |
| 求职与晋升 | 技能匹配度、面试或晋升进度、机会概率、收入预期、精力负荷 |
| 投资理财 | 可投资本金、预期收益、最大回撤、流动性、风险暴露 |

原有十个场景全部迁移到各自领域指标，并补齐可执行决策目录、替代动作、风险区间与中文阈值叙述。奶茶店创业作为第一份迁移和分支预览的基准场景。

### 6.3 新增场景首批范围

在现有十个场景完成迁移后，首批新增以下四个 JSON 场景，并分别提供 4 个 Agent 的领域动作、至少 3 个用户可选经营或人生决策、低成本替代方案、两条以上风险或干预规则和完整中文说明：

1. 电商创业：选品、渠道投放、库存周转、复购和现金储备。
2. 考公决策：岗位选择、备考投入、模考反馈、求职备选和心理负荷。
3. 高考志愿：专业选择、城市选择、院校梯度、家庭预算和职业适配。
4. 租房还是买房：租售比较、首付、月供压力、通勤、家庭与政策风险。

场景数量不作为完成标准。每个新场景必须能生成领域正确的年度摘要、预览分支、风险解释和完整报告，才可在场景库中展示。

## 7. 错误处理与兼容边界

- 旧会话缺少新增事件时，报告以已有 timeline 和快照降级展示，并标识“早期会话，过程记录不完整”。
- 画像缺少与当前判断相关字段时，Agent 显示缺失项并降低把握度。
- 场景没有可执行动作效果时，分支停留在待补充状态，不运行伪模拟。
- 历史数据库升级必须以向前兼容方式增加表或列，不破坏现有 SQLite 会话。

## 8. 验收测试

1. “怎么盈利”和“好吧”均不会改变年数、世界状态或产生年度结算。
2. 明星代言产生三条分支预览；未选择前主线快照不变；选择后仅选中分支影响下一年度。
3. 四个 Agent 都收到最新提案和相关画像，输出中文且分别包含不同评价维度；真实共识会被显式标记。
4. 145 对 150 至 350 的文案为“略低于下限 5 杯”，且同一指标在摘要、风险和报告中口径一致。
5. 周期到达后进入 `horizon_review`；续推不结算终局；结束才生成终局评分。
6. 匿名会话刷新后仍可读取；登录后可归并；其他匿名身份无法读取。
7. 每次用户与 Agent 交互、分支和年度事件均按严格递增序号存储；SSE 与数据库事件序列一致。
8. 暂停和已完成会话都能在历史页读取结构化完整报告；Markdown 导出仍可用。
9. 考研、买房、求职等场景只展示其声明的领域指标，不出现客流、月利润等创业字段。
10. 十个旧场景和四个新增场景均通过决策源校验；每个动作、分支、干预和结局只引用已声明指标。

## 实施顺序

1. 先建立输入分类、时间状态机、事件序号和 SSE 修复，恢复核心推演可信度。
2. 再建立决策目录、预览分支、画像注入、Agent 立场和中文数值叙述。
3. 将指标模型改为场景驱动，先迁移奶茶场景，再迁移十个既有场景。
4. 完成匿名所有权、事件回放报告、历史页面和旧数据降级。
5. 最后新增电商创业、考公决策、高考志愿、租房还是买房四个场景。
