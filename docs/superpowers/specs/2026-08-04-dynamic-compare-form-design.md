# 场景驱动 A/B 对比表单设计

## 目标

让 A/B 对比页可以使用所有场景，包括创业、考研、买房、升学等，而不再固定提交奶茶场景的资金、城市和年数参数。

## 方案

场景切换后，前端请求 `GET /api/scenarios/{scenario_id}`，使用其 `decision_vars` 定义渲染两套独立表单。

- 必填变量始终显示。
- 非必填变量位于“更多可选条件”，默认折叠；用户填写后才随请求提交。
- 初始值使用场景 `default`。无默认值的必填字段保持为空，并禁用开始对比按钮。
- `integer` 与 `number` 使用数字输入，`string` 使用文本输入，并展示最小值和最大值提示。
- 场景切换会重置两套表单为新场景默认值，避免不同场景变量残留。

## 边界

前端只负责按定义收集输入和基本空值校验；实际类型、范围和未知字段校验仍由后端 `make_initial_state` 完成。对比结果不持久化，不改变现有 A/B 摘要、评分和图表。

## 验收

1. 选择 `grad_exam` 后，页面提交目标院校、当前基础、备考月数和预算，不提交城市。
2. 选择 `milktea_startup` 后，页面仍能提交资金、城市和推演年数。
3. 必填变量未填写时无法发起请求，切换场景不会保留前一场景变量。
4. 后端场景 API 测试、全量后端测试和前端构建通过。
