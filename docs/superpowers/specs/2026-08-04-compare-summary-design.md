# A/B 对比摘要设计

## 目标

让用户在 A/B 对比完成后直接看懂推荐哪个方案、两者在哪些经营指标上存在差异，以及各自需要承担什么风险。

## 范围

- 保留现有双路确定性推演与趋势图。
- 新增确定性的中文对比摘要，不调用 LLM，不写入会话历史。
- 消除页面中的内部字段名、英文结果值与 JSON 字符串。

不包含：A/B 对比结果持久化、从历史页恢复对比、修改推演规则。

## 数据设计

`compare_states` 增加 `summary` 字段，包含：

- `recommendation`：推荐方案 A/B/持平、标题和可读理由。
- `metrics`：现金储备、月利润、每日客流、周边竞争门店、回本进度五个固定指标；每项包含中文名称、A/B 格式化前数值、差值和更优方案。
- `risks`：分别基于双方最终世界状态生成的中文风险提示。

比较核心仍为确定性评分和最终世界状态。推荐优先比较综合评分；分数相同则比较月利润、现金储备和风险指数，仍无法区分时返回“暂未分出优劣”。

## 前端呈现

对比结果顶部先展示推荐结论，再显示两套方案的结果和评分。差异分析改为固定中文指标表，清楚标识哪一方案更占优；风险区并排展示双方风险。趋势图和评分图使用中文图例与维度名称。

## 验收

1. `/api/simulations/compare` 返回中文摘要，且不含原始 world-state 键作为用户展示文案。
2. 优势方案、数值差异和风险提示可由相同输入稳定复现。
3. 对比页不再使用 `JSON.stringify` 或 `replace(/_/g)` 展示差异数据。
4. 后端聚焦测试和前端构建通过。
