## 一、商业化方向（面试可讲·未来规划）

【产品决策】本项目为个人学习者项目不设商业 KPI，但商业化方向是面试必答（追问"卖给谁"）。以下为 V3+ 演进路线，不在 MVP 范围。

### 1. 方向一：职业规划模拟（C 端高频）
- **用户**：大学生/应届生/转行者，在"考研/就业/考公/创业"间纠结。
- **价值**：模拟不同路径 3-5 年走向，看清各自风险与成长。
- **市场**：海量，决策焦虑强。

### 2. 方向二：创业辅助模拟（C 端 + B 端）
- **用户**：想创业者/小本创业者；B 端=创业服务机构/孵化器/园区。
- **价值**：创业前模拟验证可行性 + 识别风险 + 行动计划。
- **市场**：C 端付费意愿中，B 端（创业服务）客单高、批量采购可能。

### 3. 方向三：企业战略模拟（B 端最高价值）
- **用户**：企业战略部/投资机构，模拟"进入某市场/增加投资/调整价格"的竞争博弈。
- **价值**：多 Agent 模拟竞争对手反应 + 市场演化，输出战略路径。
- **市场**：客单最高，但销售周期长、需行业定制。

**演进路径**：C 端创业模拟器（MVP-V2）→ C 端职业规划（V3）→ B 端创业服务（V3+）→ B 端企业战略（V4+）。

## 二、面试包装

### 2.1 30 秒电梯演讲（高级版）

> 我设计了一套基于 Multi-Agent 的**决策模拟引擎**，通过 LangGraph 管理长期状态演化，通过决策知识库（RAG）和 MCP 引入外部事实约束，让多个具有不同目标的 Agent 在同一个世界状态中进行博弈，最终生成可解释的决策路径、风险分析和 A/B 方案对比。核心不是让 AI 给答案，而是模拟不同选择的后果、提供风险认知——比如输入"辞职开奶茶店、预算 20 万、杭州"，系统模拟市场/环境/个人/风险四类 Agent 3 年博弈，输出分支时间线、可行性评分、关键风险节点和 30 天行动计划。

### 2.2 一句话定位（防"游戏感"）

❌ 不要说：我做了一个人生模拟游戏。
✅ 要说：我设计了一套基于 Multi-Agent 的决策模拟引擎。

### 2.3 项目亮点叙事（3 个技术故事）

1. **两层图架构**：外层 LangGraph 管时间线演化，内层管每个 Agent 独立决策——解耦后并行度高、可调试、单 Agent 出 bug 不影响全局。
2. **Simulation Judge Agent 自洽裁判**：回合末结构化校验 Agent 决策与世界状态是否自洽，不自洽带 revise 回退重生成——防推演崩坏。
3. **决策源解耦**：结局判定 100% 状态机+决策源，LLM 只负责"说"——可断 LLM 用 stub 复现判定（AC7），崩盘率骤降、成本骤降。

## 三、10 个面试追问标准答案

### Q1. 为什么需要多个 Agent？

> 单一 Prompt 既要懂行业又要懂财务又要懂政策，上下文污染导致幻觉叠加。按职责拆分 4 个 Agent（市场/环境/个人/风险），每个聚焦单一视角，决策质量更高、可调试、可并行。Agent 数量服从职责清晰度，不服从"看起来很多"。

### Q2. Agent 之间如何避免互相胡编？

> 三层兜底：①决策源解耦——结局判定 100% 状态机+决策源，不靠 LLM 记忆；②决策知识库实时召回 Top-K 行业基准拼入 Prompt 前缀约束生成；③Simulation Judge Agent 回合末结构化校验各 Agent 行动与世界状态自洽，不自洽带 revise 回退重生成。

### Q3. 为什么不用普通 ChatGPT？

> ChatGPT 是单 LLM 一问一答，三个硬伤：①无长期状态管理——多年度演化它会忘；②无多视角博弈——它只给一个"综合答案"而非市场/环境/个人/风险各自立场；③无事实约束——它靠记忆可能胡编。我的系统用 LangGraph 管状态演化、多 Agent 分视角博弈、决策知识库+MCP 约束事实，输出可追溯的时间线+风险+行动计划，是 Simulation 不是 Chat。

### Q4. RAG（决策知识库）解决什么问题？

> 解决"AI 胡编行业数据"。决策知识库存行业规律/失败案例/政策/财务模型/风险模式，Agent 决策前强制召回 Top-K 拼入 prompt，把"靠 LLM 记忆"变"靠数据约束"。四步保障：预处理入库→实时召回→事后校验→动态更新。

### Q5. MCP 为什么需要？

> 演示 Agent↔工具 范式。Agent 模拟中自主决定"需查证"（如查某城市竞品数/政策补贴），LangGraph 注入 MCP 工具调用返回结构化 JSON 进入世界状态。是 MCP 最该示范的点（非媒体生成）。本项目 Mock+少量真 API 混合，零成本可离线。

### Q6. 如何保证模拟结果可信？

> 四道防线：①定位"模拟后果非给答案"——不承诺预测准确，提供风险认知；②决策源解耦——结局判定走状态机+决策源，可断 LLM 用 stub 复现判定（AC7）；③Simulation Judge Agent 自洽校验——抽样 10 年无逻辑冲突（AC4）；④透明可追溯时间线+事件溯源——每步 Agent 行动可审计回放，用户能看清"为什么走到这"。强免责声明管理预期。

### Q7. 如果推演 100 年怎么办？

> 上下文截断+摘要——Agent 记忆按 token 预算只保留最近 N 年+旧决策摘要，绝不无限 append；摘要低频且可缓存。技术上无上限，但 100 年意义存疑（行业基准早过期）——产品上限制 span_years ≤ 5 年保证决策知识库时效性。

### Q8. 如何降低 LLM 成本？

> 分层模型路由——快模型（DeepSeek/本地7B）扛 80% 年度决策，慢模型（Claude/GPT-4o）仅校验/裁决/行动计划。单次模拟成本 < 1 元。另：流式输出、4 Agent 并行、检索缓存、预生成、意图分类前置、本地小模型兜底。

### Q9. 为什么状态机不用 LLM 控制？

> 状态机管确定性流程（年度推进/结局判定/自洽校验），必须可预测可测试。LLM 是概率性的，让 LLM 控状态机=把确定性交给掷骰子，无法复现 bug、无法 AC7（断 LLM 用 stub 复现判定）。解耦后 LLM 只负责"说"，状态机负责"判"，各司其职。

### Q10. 如果商业化，你卖给谁？

> 三段演进：①C 端创业模拟器——想创业者/小本创业者，付费意愿中，决策焦虑转化；②B 端创业服务——孵化器/园区/创业服务机构，批量采购帮创业者验证可行性，客单高；③B 端企业战略——企业战略部/投资机构模拟竞争博弈，客单最高。演进路径 C 端验证引擎 → B 端规模化变现。MVP 先 C 端创业跑通引擎与模板，再按同内核扩 B 端场景。

## 五、Demo 演示流程（面试现场建议）

1. **开场 30 秒**：电梯演讲（2.1）。
2. **现场改参数**：输入"辞职开奶茶店、20 万、杭州、3 年" → 改预算为 10 万 → 改城市为上海 → 展示三种不同结局（AC9 炸场点）。
3. **关键节点干预**：模拟到第 2 年现金流告急 → 弹选择 → 选"降本裁员" → 展示走向改变。
4. **A/B 对比**：创业方案 vs 继续就业方案 → 五维表并排。
5. **行动计划**：展示 30 天可执行清单（不是虚话）。
6. **追问应对**：用第三/四节标准答案。

> 现场注意：MVP-0 用 Mock 数据先跑通逻辑，面试官问数据真实性→用 Q6 四道防线 + 真实度分层回答。
